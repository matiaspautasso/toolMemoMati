# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

`toolMemoMati` is a **driver/installer** — a portable toolkit that sets up a persistent memory framework (Serena + SQLite-RAG + Engram) in any target project. It does not run in itself; it generates and installs files into other projects.

Key distinction: this repo contains **templates, scripts, schemas, and specs**. The actual memory data lives in the target project under `memory/`.

## Architecture

```
toolMemoMati/              ← this repo (the driver)
├── install/               ← PowerShell installers
├── templates/             ← files generated into target projects
│   ├── mcp.json.template
│   ├── CLAUDE.md.template
│   └── skills/memory-bootstrap.md
├── memory-auditor/        ← audit engine (portable, AI-agnostic)
│   ├── core/              ← audit-engine.md — edit manually (spec)
│   ├── adapters/          ← GENERATED by the script, never edit manually
│   └── scripts/memory-audit.ps1
├── schemas/               ← JSON schemas for RULE-*, DEC-*, BUG-* files
└── scripts/               ← export-rules.ps1, validate-memories.ps1
```

The installer entry point is `install/memory-framework-install.ps1`. It calls `install/check-mcps.ps1` as a prerequisite.

## Running the installer

```powershell
# Install into a target project
.\install\memory-framework-install.ps1 -ProjectPath "C:\path\to\project"

# Dry run (no changes, shows what would happen)
.\install\memory-framework-install.ps1 -ProjectPath "C:\path\to\project" -DryRun

# Skip MCP availability check
.\install\memory-framework-install.ps1 -ProjectPath "C:\path\to\project" -SkipMcpCheck
```

## Key design decisions (read before touching installer logic)

**DEC-001** — SQLite-RAG is scoped per project. The `.sqlite` file goes in `{project}/memory/business-rules.sqlite` (not global). The versionable export is `memory/business-rules/rules.export.jsonl`.

**DEC-002** — CLAUDE.md injection uses HTML comment markers `<!-- MEMORY-FRAMEWORK:START -->` / `<!-- MEMORY-FRAMEWORK:END -->`. Never overwrite the whole file. Three cases: (a) no CLAUDE.md → create from template, (b) exists without markers → append section, (c) exists with markers → replace only that block.

**DEC-003** — The auditor (`memory-audit.ps1`) is a standalone PowerShell script with no AI dependency. It generates adapter files for each detected environment (`.claude/` → claude-code adapter, `.cursor/` → cursor adapter). Adapters are outputs — never edit them manually; edit `core/audit-engine.md` instead.

**DEC-004** — Audit triggers: manual (`/memory-audit`), automatic every 10 sessions (counter in `memory/.audit-counter`), and pre-PR hook.

## Memory format conventions

Files in `memory/` of target projects follow these naming and YAML frontmatter conventions:

| Type | Filename | ID format |
|------|----------|-----------|
| Business rule | `memory/business-rules/RULE-{MODULE}-{NNN}.md` | `RULE-VENTAS-001` |
| Technical decision | `memory/decisions/DEC-{AREA}-{NNN}.md` | `DEC-DB-001` |
| Bug fix | `memory/bugfixes/BUG-{MODULE}-{NNN}.md` | `BUG-AUTH-001` |

Valid `estado` values: `vigente` | `dudosa` | `obsoleta` | `reemplazada`

## What NOT to version in target projects

```
memory/business-rules.sqlite    ← binary, changes constantly
memory/.audit-counter           ← ephemeral session counter
memory/cache/
.serena/index/
```

## Authority hierarchy (conflict resolution)

When two memory sources contradict each other:
```
1. Current code  →  2. Passing tests  →  3. Active docs  →  4. SQLite-RAG (confidence ≥ 0.8)  →  5. Engram  →  6. Chat context
```

No agent can elevate a memory to a higher tier without explicit user authorization.

## Authorization levels for memory writes

| Risk | Examples | Required action |
|------|----------|-----------------|
| Low | session summary, minor bug | automatic |
| Medium | technical decision, new convention | show proposal → wait for confirmation |
| High | business rule, delete memory, change authority hierarchy | always confirm — describe impact first |
