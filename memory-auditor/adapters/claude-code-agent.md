# Memory Audit Adapter — Claude Code

> This file is regenerated by `memory-audit.ps1` after each audit run. Do not edit manually.
> The template version (what you're reading now) is used before the first audit is run.

## How to use this adapter

After running `memory-audit.ps1`, this file will contain the audit summary and specific
instructions for this project. To trigger it, tell Claude Code:

> "Read the audit adapter at `memory-auditor/adapters/claude-code-agent.md` and process
> the audit report following the authorization protocol."

Or use the skill directly:

> "/memory-audit"

## Authorization protocol (always applies)

| Action | Risk | Required before acting |
|--------|------|------------------------|
| Mark entry as `dudosa` | Low | Automatic — inform user after |
| Mark entry as `obsoleta` | Medium | Show proposal → wait for `[A]pprove` |
| Delete entry file | High | Always confirm — describe full impact first |
| Resolve contradiction | Medium | Show both entries + resolution → wait for `[A]pprove` |
| Change authority hierarchy | High | Always confirm |

## Soft-delete protocol

Never delete a memory file directly. Always:
1. Update `estado` to `obsoleta`
2. Set `motivo_cambio` to the reason
3. Update `fecha_actualizacion` to today
4. Propose file deletion to the user separately

## Instruction template (populated after first audit)

```
An audit report exists at memory/audits/audit-YYYY-MM-DD.md.

1. Read the full report
2. For each Obsoleta entry: present to user as HIGH-risk action, wait for approval
3. For each Dudosa entry: present review options (update / mark obsoleta / keep), MEDIUM risk
4. For each Contradiction: show both entries, apply authority hierarchy, propose winner, MEDIUM risk
5. After each approved change: update the .md file's frontmatter (estado + fecha_actualizacion)
```
